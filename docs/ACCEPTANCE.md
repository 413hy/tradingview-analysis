# 验收说明

本文件描述仓库代码已经验证的范围，以及仍需在目标部署环境完成的真实验收。它不包含开发机器的密钥、账户数据、运行数据库或网络配置。

## 已完成的代码验证

- Ruff 静态检查通过。
- 55 项自动化测试通过；包括候选与证据校验、两阶段发布、独立 PostgreSQL schema、REST 鉴权与消费、信号去重、订单未知响应、保护重试预算、重启恢复、成交核账、设置并发更新、Bot 授权和轮询恢复。
- 使用明确标注的合成行情完成过本地 Codex 两阶段结构化调用，正常流程为两次调用；结果没有发布到生产信号表。
- 两个 Telegram Bot 的 `getMe`、webhook 检查、chat 检查、发送、编辑、内嵌键盘和删除接口曾在开发环境验证；Bot 设置修改仍遵循预览、保存、审计流程。
- TradingView Coins/CEX 六类榜单和两类 Ideas 采集器完成过公开页面验证；显式 fixture Universe 的结果不等同于 Binance 实时 Universe 验收。
- 模拟交易覆盖实际成交目标冻结、SL 优先、reduce-only、部分成交、重复信号、未知订单响应、明确拒绝重试、人工保护核对和无成交证据不结算等分支。

## 部署环境必须重新验证

以下事项依赖目标设备、网络、账户权限和第三方服务，不能由仓库测试替代：

1. Binance 正式 USDⓈ-M 公开接口能够返回实时 Universe 和行情。
2. Binance Demo API Key 具备所需读取/交易权限，账户采用单向持仓和单资产保证金模式。
3. 完整真实周期从 Raw → Pre-Rank → Top10 → Market → Signals 成功；来源时间、币种映射和市场新鲜度均有效。
4. Demo 入场、实际成交、SL/TP 创建、订单触发、重启恢复和最终成交核账全部通过。
5. 两个独立 Bot Token、管理员 chat/user 白名单、MTProto 用户会话和 TradingView persistent profile 正常。
6. 任何可选付费数据源都使用其实际套餐密钥独立验证；无密钥时跳过是预期行为。

## 当前口径与限制

- 分析失败不会发布新信号，也不会刷新旧信号时间。
- API 信号展示期限和 60 秒开仓消费期限是两个字段。
- 交易服务只允许 Binance USDⓈ-M Demo 私有接口；仓库没有正式盘开关。
- `net_pnl` 是系统归属成交的已实现盈亏减手续费，不包含资金费。
- 外部人工平仓、清算或缺少完整成交证据时保持待核账并告警，不编造关闭原因或盈亏。
- 自动化测试、合成模型输入、公开页面采集和健康检查都不能单独证明真实交易链路通过。
